# 学生使用手册

## 1. 这个系统用来做什么

NebulaGrid 是实验室的 GPU 任务与实验文件管理平台。你可以在浏览器里完成这些事情：

- 查看自己可用的计算节点和 GPU 状态。
- 上传、整理、编辑和下载自己的项目文件。
- 查看、检测、复制和维护自己可用的 Python/conda 环境。
- 提交训练任务，查看等待、运行和历史结果。
- 查看任务日志，定位路径、依赖、CUDA 或脚本错误。
- 修改自己的姓名、密码、Samba 状态和登录设备。

几个常用概念：

- **项目路径**：训练命令执行时所在的文件夹，通常是代码仓库目录。
- **执行命令**：真正运行的命令，例如 `python train.py --config configs/a.yaml`。
- **等待区**：任务已提交，但暂时还没有开始运行。
- **执行区**：任务正在准备或运行。
- **历史区**：任务已经完成、失败、被取消或因节点异常结束。

## 2. 登录与账号安全

1. 打开浏览器访问 NebulaGrid 地址。
2. 输入管理员分配的用户名和密码。
3. 登录后建议先进入 `账号管理` 修改密码。
4. 如果页面提示登录失效，请重新登录；如果仍然失败，联系导师或管理员。

第一次登录后建议按这个顺序检查账号：

1. 看页面右上角或 `账号管理` 中显示的用户名，确认不是借用了别人的账号。
2. 修改初始密码，密码不要和其他网站、邮箱或服务器密码相同。
3. 检查 `登录设备` 列表，只保留自己正在使用的浏览器设备。
4. 暂时不需要 Windows 网络共享时，不要急着开启 Samba；需要从 Windows 文件资源管理器直接访问个人目录时再开启。

安全建议：

- 不要把账号密码借给他人。
- 在公共电脑上使用后，先在 `账号管理` 下线该设备，再退出登录。
- 发现陌生登录设备时，先下线设备，再修改密码。
- Samba 开启时需要输入当前平台密码；如果不确定是否需要 Samba，可先保持关闭。

## 3. Samba、Windows 网络共享与 SSH 登录

这一节用于解决“浏览器传大文件不方便，想像打开网络硬盘一样访问自己的目录”以及“需要用终端登录自己的账号”的问题。只有管理员已经在主节点启用了 Linux 子账户和 Samba 管理后，下面的步骤才会生效。

### 开启 Samba 服务

Samba 是给 Windows、macOS 或 Linux 桌面系统访问个人目录的文件共享服务。NebulaGrid 中的 Samba 开关是按用户单独开启的，新账号默认关闭。

开启步骤：

1. 登录 NebulaGrid。
2. 进入 `账号管理`。
3. 找到当前账号卡片中的 `Samba 服务` 或类似开关。
4. 勾选开启。
5. 在弹窗或密码框中输入你当前的 NebulaGrid 登录密码。
6. 保存后等待状态变成 `已启用`。

需要注意：

- 这里输入的是你当前的平台密码，不是管理员密码，也不是 Windows 开机密码。
- 开启后，Samba 用户名通常就是你的平台用户名。
- 你以后在平台修改密码后，已开启 Samba 的账号会同步更新 Samba 密码。
- 如果状态显示 `未执行` 或 `失败`，先不要反复开关，记录提示信息并联系导师或管理员。

### 在 Windows 连接自己的共享目录

假设管理员给你的主节点地址是 `<master-ip>`，你的平台用户名是 `<user_name>`。Windows 资源管理器里不要只输入 `\\<master-ip>`，因为个人目录共享通常不会在根目录中列出来。应直接访问自己的共享名：

```text
\\<master-ip>\<user_name>
```

例如用户名是 `test1`，主节点 IP 是 `192.168.0.1`，就在 Windows 资源管理器地址栏输入：

```text
\\192.168.0.1\test1
```

也可以在 Windows 中固定成一个盘符：

1. 打开 `此电脑`。
2. 点击 `映射网络驱动器`。
3. 选择一个盘符，例如 `Z:`。
4. 文件夹填写 `\\192.168.0.1\test1`。
5. 勾选 `使用其他凭据连接`。
6. 输入平台用户名和平台密码。

弹出登录窗口时：

- 用户名填写平台用户名，例如 `test1`。
- 密码填写你开启 Samba 时使用的当前平台密码。
- 如果 Windows 要求写成 `服务器\用户名`，可填写 `192.168.0.1\test1`。
- 不建议在公共电脑上勾选“记住我的凭据”。

如果之前输错过密码，Windows 可能会缓存错误凭据。可以打开 Windows 的 `cmd`，把下面命令中的 IP 和用户名换成自己的：

```bat
net use \\192.168.0.1\test1 /delete /y
cmdkey /delete:192.168.0.1
net use \\192.168.0.1\test1 /user:test1 *
```

最后一条命令会提示输入密码。密码输入时可能不显示字符，这是正常现象。

常见错误判断：

- 提示找不到网络路径：确认主节点 IP 是否正确，是否在校园网、实验室内网或 VPN 内。
- 提示账号密码错误：确认 Samba 已启用，并使用平台用户名和平台密码。
- 能登录平台但无法连接共享：可能是管理员未启用 Samba 后端、445 端口被防火墙拦截，或 Windows 缓存了旧凭据。
- 只能看到自己的目录，看不到全员共享目录：这是正常设计；公共资料建议通过页面里的 `共享文件夹` 视图访问。

### SSH 到自己的账号

SSH 适合用终端执行少量命令、用 `scp`/`rsync` 传大文件、查看目录结构或调试脚本。普通用户通常只需要 SSH 到主节点，不要直接登录计算节点。

在 Windows PowerShell、Windows Terminal、macOS 终端或 Linux 终端中运行：

```bash
ssh <user_name>@<master-ip>
```

例如：

```bash
ssh test1@192.168.0.1
```

第一次连接会提示是否信任主机指纹，确认 IP 是管理员给出的主节点地址后输入 `yes`。随后输入你的平台密码。登录成功后，默认会进入你的个人工作目录，通常对应 Web `文件管理` 里的个人目录。

常用命令：

```bash
pwd
ls
cd my_project
du -sh .
```

从 Windows 上传文件到个人目录，可在本机 PowerShell 中运行：

```bash
scp .\dataset.zip test1@192.168.0.1:~/dataset.zip
```

从个人目录下载结果到 Windows，可运行：

```bash
scp test1@192.168.0.1:~/outputs/result.csv .\result.csv
```

使用 SSH 时不要做这些事：

- 不要删除不认识的系统目录或共享目录。
- 不要在 SSH 中长期占用 GPU 训练；训练任务应通过 NebulaGrid `任务管理` 提交，让平台调度 GPU。
- 不要手动设置 `CUDA_VISIBLE_DEVICES` 绕过平台分配，否则任务可能出现调度错误。
- 不要把密码、密钥、数据集授权文件放到共享文件夹。

## 4. 总览与节点监控

`总览` 页面用于判断当前是否适合提交任务。

节点状态由后台监控长连接刷新。管理员配置的监控间隔通常是几秒一帧；如果主节点到计算节点的监控连接断开，或连接还在但长时间没有收到有效状态，页面会把该节点显示为离线。

你会看到：

- **节点总数 / 在线节点**：当前可见的计算节点数量。
- **GPU 总数 / 可用 GPU**：当前可见 GPU 的总体情况。
- **运行任务**：当前正在运行的任务数量。
- **CPU、可用内存、上传、下载**：节点实时负载。
- **GPU 使用率、显存使用量**：判断显卡是否繁忙。
- **调度占用**：这张 GPU 是否已经被平台任务占用。

怎么看资源是否合适：

- 单卡训练通常需要至少 1 张显存较空的 GPU。
- 如果指定了 GPU 型号，要确认可见节点中有该型号且符合显存需求；同时指定节点时，系统只会在该节点内寻找该型号。
- 显存很高时，任务可能容易因为显存不足失败。
- 节点离线时，不要指定该节点提交任务。

## 5. 文件管理与在线编辑

`文件管理` 默认显示你的个人目录。页面左侧是文件列表，右侧是文件预览或编辑区域。

常用操作：

- `根目录`：回到你的个人目录根。
- `上级`：返回上一层目录。
- 点击文件夹或 `进入`：打开下级目录。
- 点击文本文件：在右侧预览或编辑。
- `保存`：保存右侧编辑器里的文件内容。
- `上传到当前目录`：把本地文件上传到当前打开的文件夹。
- `新建文件夹` / `新建文件`：创建新的目录或文本文件。
- `重命名`、`复制到`、`移动到`、`删除`：对选中的文件或文件夹操作。
- `打包成 zip`：把选中的文件夹打包。
- `解压压缩包`：把支持的压缩包解压到指定目录。
- `下载选中`：下载选中文件或文件夹。
- `文件权限`：打开脚本文件后查看权限位；提交 `.sh` 等脚本任务前，点击 `授予执行权限`，让主账户可以执行该文件。

共享文件夹：

- `共享文件夹` 里通常放公共数据、课程材料或共享结果。
- 在共享视图中，能复制到自己目录的文件才建议复制。
- 不要把隐私数据、密码、密钥或未确认可公开的数据放到共享文件夹。

使用提醒：

- 训练命令里的相对路径，都是相对于提交任务时选择的 `项目路径`。
- 如果任务命令直接运行 `./train.sh` 这类脚本路径，先在文件预览下方确认主账户执行状态为 `可执行`；如果命令写成 `bash ./run.sh`，通常不依赖脚本本身的执行位。
- 删除、移动、覆盖保存前先看清当前路径。
- 重要代码建议用 Git 或本地备份保存。
- 如果文件操作失败，先检查是否选中了文件、目标目录是否存在、压缩包格式是否受支持。
- 上传/下载大文件时，应使用 `scp` 命令，不建议通过前端上传/下载。

## 6. 环境管理

`环境管理` 用于查看和维护你可用的 Python/conda 环境。

你会看到：

- **名称**：环境名。
- **来源**：系统导入、用户导入、环境副本等。
- **状态**：可用、导入中、复制中、安装中、检测中等。
- **路径**：环境所在路径。
- **版本**：Python 版本；环境检测还会记录已安装 PyTorch 的版本、编译 CUDA 和支持的 GPU 架构。

常用操作：

- `刷新环境列表`：重新读取环境列表。
- `导入环境`：从自己的文件目录选择打包好的 conda 环境 zip，导入为可用环境。
- `检测`：检查 Python、PyTorch、TensorFlow、CUDA、PyTorch 支持的 GPU 架构和包信息。安装或删除 PyTorch 后平台会自动刷新记录；环境没有 PyTorch 时不会保存旧的 PyTorch 数据。
- `查看日志`：查看检测、复制、导入或安装包过程。
- `创建副本`：从一个可用环境复制出自己的环境。
- `安装包`：向可修改的环境安装 conda 包、wheel、本地包或源码包。
- `删除包`：从环境中删除你选择的包，基础包会被保护。
- `删除环境`：删除自己有权限删除的环境。

### 从其他 Ubuntu 电脑导入环境

如果你已经在另一台 Ubuntu 电脑上配好了 conda 环境，可以把那个环境打包后导入 NebulaGrid。推荐流程如下：

1. 在那台 Ubuntu 电脑上找到环境目录。环境必须位于 Linux 版 Anaconda3 或 Miniconda3 的 `envs` 目录下，例如 `~/miniconda3/envs/<env_name>` 或 `~/anaconda3/envs/<env_name>`。
2. 进入 `envs` 目录，把整个环境目录打成 zip。不要只压缩 `bin`、`lib` 或 `conda-meta` 子目录，也不要把多个环境打进同一个 zip：

   ```bash
   sudo apt install -y zip
   cd ~/miniconda3/envs
   zip -r <env_name>.zip <env_name>
   ```

   如果你使用的是 Anaconda3，把 `cd` 那一行换成：

   ```bash
   cd ~/anaconda3/envs
   zip -r <env_name>.zip <env_name>
   ```

3. 用自己的平台账号把 zip 传到主节点个人目录。把 `<user_name>` 换成你的平台用户名，把 `<master-ip>` 换成管理员给你的主节点地址：

   ```bash
   scp <env_name>.zip <user_name>@<master-ip>:~/<env_name>.zip
   ```

   上传完成后，在 Web `文件管理` 的个人根目录 `/` 下应能看到 `/<env_name>.zip`。

4. 进入 Web `环境管理`，点击 `导入环境`，从个人目录中选择刚上传的 `/<env_name>.zip`，填写目标环境名并确认。
5. 页面会显示 `导入中 -> 修复中 -> 测试中 -> 可用`。系统会自动解包、复制到集群的 conda 环境目录、修复旧路径，再运行检测。检测通过后，这个环境才会显示为可用。

环境包只能来自 Linux x86_64/amd64 系统中的 Anaconda3/Miniconda3。Linux ARM、MIPS 等其他架构不能使用；Windows 和 macOS 的 conda 环境禁止上传。系统会自动检测环境包的可用操作系统和执行情况，非 Linux 或无法在当前集群激活的环境会被拒绝或标记为导入失败。

### 在指定节点编译安装环境包

有些包不能直接安装现成 wheel，需要在某台节点上编译，例如依赖 `gcc`、`g++`、`clang`、`nvcc` 或 CUDA 头文件的源码包。这类包建议使用环境管理里的 `指定节点编译` 功能，而不是自己 SSH 到节点上手动改环境。

操作步骤：

1. 进入 `环境管理`。
2. 选择要维护的环境，点击 `安装包`。
3. 选择包来源和安装方式，例如本地 wheel、源码包、`pip install .` 或 `python setup.py install`。
4. 在 `指定节点编译` 区域点击 `在指定节点`。
5. 等待弹窗完成节点探测。
6. 在左侧选择目标节点。主节点和你可见的计算节点会一起显示。
7. 看右侧编译器信息，确认需要的 `gcc`、`g++`、`clang` 或 `nvcc` 不是 `未安装`。
8. 按需要选择 GPU 模式。
9. 点击 `确认`，回到安装表单。
10. 点击 `执行安装`，等待状态从 `安装中` 变为完成或失败。
11. 如果失败，打开 `查看日志`，把最后几十行错误发给导师或管理员。

GPU 模式怎么选：

- `默认`：不额外限制 CUDA 可见性，适合普通源码编译或不确定是否需要 GPU 的安装。
- `CPU`：隐藏 GPU，让安装过程尽量走 CPU 路径，适合不希望编译脚本误占 GPU 的情况。
- 勾选具体 `GPU`：只让安装过程看到选中的 GPU，适合必须在某张 CUDA GPU 上编译或探测的包。

注意：

- 指定节点编译是环境安装作业，不是普通训练任务；它不会进入任务等待区。
- 编译安装可能占用 CPU、内存、磁盘 IO，少量使用即可，不要重复点击。
- 环境显示 `安装中` 时，不要同时安装或删除包。
- 如果目标节点离线、SSH 异常、NFS 路径不一致或缺少编译器，安装会失败，需要管理员处理节点环境。
- 不确定包是否需要指定节点时，先用普通安装；普通安装失败并提示编译器、CUDA 或 GPU 相关问题时，再尝试指定节点编译。

环境排查顺序：

1. 先看环境状态是否是可用。
2. 点 `检测`，确认 Python 和深度学习框架是否正常。
3. 看 CUDA 信息是否与你的训练代码要求一致。
4. 安装包失败时打开 `查看日志`，重点看缺依赖、版本冲突、包格式错误。
5. 如果日志里出现编译器、CUDA 头文件、`nvcc`、GPU 探测或源码编译错误，再考虑 `在指定节点` 编译。
6. 不确定要不要改公共环境时，先 `创建副本` 再修改。

## 7. 添加单个任务

进入 `任务管理`，点击 `添加任务`。

字段说明：

- **选择环境**：任务运行时使用的 Python/conda 环境。
- **项目路径**：代码所在目录。建议用文件夹选择器选择，不要手写。
- **执行命令**：一行训练命令，例如 `python train.py --config configs/vit.yaml`。
- **指定计算节点**：可以留空，让系统从你可用的节点中安排；也可以选择某个可见节点。
- **需求的 GPU 数量**：单卡训练常填 `1`；CPU 任务填 `0`。
- **GPU 型号**：可用型号以卡片显示。选择环境后，精确命中 PyTorch `sm_xx` 的卡片显示绿色“原生支持”；同一主版本内可使用较低次版本 cubin 的卡片显示绿色“同主版本兼容”；没有兼容 SM 代码的卡片显示红色“不支持”。`compute_xx` 不参与判断，避免把理论 PTX JIT 能力误认为可用。这些是提示，你仍可勾选并强制使用；只选型号时系统会在你可见的节点中匹配该型号，和指定节点同时选择时只在该节点内匹配。
- **前驱任务**：当前任务要等另一个任务成功后再运行时使用。
- **任务描述**：可写实验名、参数组或备注，方便以后查找。
- **紧急任务**：少量需要优先运行的任务可勾选。
- **复用 GPU**：仅当你确认任务显存占用小、可以共享 GPU 时再勾选。
- **挂起任务**：先保存任务但暂不运行，适合先批量录入后再逐个放开。

不指定 GPU 型号时，系统只会排除红色“不支持”的 GPU；原生支持、同主版本兼容和信息未知的 GPU 都按原有资源顺序正常调度，不会因为兼容等级重新排序。若当前只剩不支持的 GPU，任务会保持等待。显式勾选型号表示你接受提示并强制选择该型号，此时调度器完全忽略兼容状态，不会替你改掉选择。不指定计算节点时，系统仍会结合节点权限和共享顺序选择资源。

单任务示例：

```text
项目路径：/my_project
环境：torch-env
GPU 数量：1
执行命令：python train.py --config configs/vit.yaml --batch-size 128
描述：vit baseline batch128
```

注意：

- 命令必须是一行。
- 命令里的相对路径以 `项目路径` 为起点。
- 如果脚本依赖数据集、配置文件、输出目录，请先在 `文件管理` 里确认它们存在。
- 不要在命令里写会影响其他用户或系统目录的危险操作。

## 8. 批量添加任务

`批量添加` 适合一次提交多条相似训练命令。批量任务会共用环境、项目路径、节点、GPU 数量、GPU 型号等设置，每一行命令生成一个独立任务。

命令输入规则：

- 每行一条命令。
- 空行会忽略。
- 以 `#` 开头的整行会忽略。
- 行内 `#` 后面的内容会被当作注释忽略；如果你的命令本身需要 `#`，请谨慎。

示例：

```text
python train.py --config configs/a.yaml
python train.py --config configs/b.yaml
# 下面这个实验暂时不跑
# python train.py --config configs/c.yaml
python train.py --config configs/d.yaml  # 注释会被忽略
```

提交后建议先在 `等待区` 检查任务数量、环境、项目路径和命令是否正确。

## 9. 修改、挂起、删除、中止与重新提交

任务管理页面分为 `等待区`、`执行区`、`历史区`。单击任务行选中任务，双击任务行可查看日志。

常用操作：

- `修改选中任务`：用于修改等待区、挂起任务或历史任务。运行中的任务不能修改。
- `挂起/取消挂起选中任务`：让等待任务暂停或恢复。
- `删除选中任务`：删除等待或历史任务记录。删除前会提示是否包含后继任务。
- `中止选中任务`：停止自己的运行任务。
- `重新提交`：把历史任务复制成一个新任务，常用于修正代码或参数后再跑。
- `查看所有历史任务`：历史区默认可能只加载最近记录，点击后查看全部。
- `查看任务日志`：打开当前选中任务的日志抽屉。

常见状态：

- `等待`：任务正在排队。
- `挂起`：任务已保存，但暂不运行。
- `准备中 / 派发中`：任务正在进入运行前准备阶段。
- `运行中`：任务正在执行。
- `完成`：任务正常结束。
- `失败`：脚本、环境、路径或依赖等原因导致失败。
- `已取消`：任务被主动中止。
- `节点掉线`：运行过程中节点异常。
- `调度错误`：任务运行资源与申请资源不一致等异常，命令或代码里不能有任何 `CUDA_VISIBLE_DEVICES`，否则会出现调度问题。

## 10. 查看任务日志

查看方式：

1. 在 `任务管理` 中选中任务。
2. 点击 `查看任务日志`，或双击任务行。
3. 日志抽屉打开后，会显示任务命令和日志内容。
4. 可使用自动刷新、暂停刷新、手动刷新和复制命令。

日志怎么看：

- 先看最后几十行，通常最接近失败原因。
- Python 报错重点看 `Traceback` 最后几行。
- 路径错误常见关键词：`No such file or directory`、`FileNotFoundError`。
- 缺包常见关键词：`ModuleNotFoundError`、`ImportError`。
- CUDA 问题常见关键词：`CUDA out of memory`、`CUDA error`、版本不匹配。
- 任务刚提交时日志可能为空，等任务进入运行后再刷新。

## 11. 推荐使用流程

1. 登录系统。
2. 进入 `总览`，确认有可用节点和 GPU。
3. 进入 `文件管理`，上传代码、配置文件和需要的数据索引。
4. 进入 `环境管理`，检测环境是否可用。
5. 回到 `任务管理`，点击 `添加任务` 或 `批量添加`。
6. 选择环境、项目路径、GPU 数量和执行命令。
7. 提交后观察 `等待区` 和 `执行区`。
8. 任务开始后查看日志，确认没有路径、依赖或 CUDA 错误。
9. 任务结束后在 `历史区` 查看状态。
10. 失败任务先修正代码、环境或参数，再 `重新提交`。

## 12. 常见问题排查

### 登录失败

- 检查用户名和密码是否正确。
- 确认账号没有被停用。
- 忘记密码时联系导师或管理员重置。

### 看不到节点或 GPU

- 节点可能离线或维护中。
- 节点可能没有分配给你。
- 共享范围可能不包含你。
- 需要使用某个私有节点时，请联系导师或管理员确认权限。

### 任务一直在等待

- 当前可用 GPU 不足。
- 指定节点离线或不可用。
- 指定 GPU 型号在候选节点中没有满足条件的空闲显卡，或显存不足。
- 前驱任务还没有成功完成。
- 任务处于挂起状态。

### 任务一运行就失败

- 查看任务日志最后部分。
- 检查项目路径是否选对。
- 检查命令是否能在项目路径下找到脚本。
- 检查环境是否可用、缺不缺包。
- 检查 CUDA、PyTorch、TensorFlow 版本是否匹配。
- 如果提交时型号显示红色“不支持”，可先取消型号强制选择让系统使用原生/同主版本兼容卡，或升级环境中的 PyTorch 后重新检测。
- 检查数据集、配置文件、输出目录是否存在。

### 日志为空或不刷新

- 任务可能还没有真正开始运行。
- 手动点击刷新。
- 切换到执行区或历史区确认任务状态。
- 如果任务已经失败但仍没有日志，联系导师或管理员。

### 文件看不到或打不开

- 确认当前是否在正确目录。
- 共享视图可能是只读或只允许复制。
- 文本编辑器只适合查看和编辑文本文件，不适合打开大二进制文件。
- 压缩包解压失败时，确认格式是否为系统支持的 zip/tar/tar.gz/tar.bz2/tar.xz。

### 环境检测或安装包失败

- 先打开环境日志。
- 检查包格式、依赖版本和 Python 版本。
- 复杂依赖建议先创建环境副本，再尝试安装。
- 不确定如何处理时，把环境名、任务号和日志截图发给导师或管理员。
