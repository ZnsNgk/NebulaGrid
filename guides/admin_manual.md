# 管理员使用手册

## 1. 管理员负责什么

管理员拥有全局维护权限，负责平台可用性、账号关系、节点资源、任务异常、环境维护和审计追踪。

管理员可以：

- 查看全局节点、GPU、任务和资源状态。
- 管理所有用户、导师学生关系、登录设备和密码。
- 新增、修改、重连、强制下线和删除计算节点。
- 查看、提交、修改、中止、删除和重新提交全局任务。
- 维护文件、共享目录和环境。
- 修改系统设置。
- 查看审计日志，追踪关键操作。

操作原则：

- 危险操作前先确认影响范围。
- 删除、强制下线、停用账号、中止任务等动作应能通过审计解释清楚。
- 优先用页面提供的操作，不直接改数据库或文件。
- 遇到资源异常时，记录节点名、任务号、用户、时间和日志片段。

## 2. 登录、安全与账号自检

1. 使用管理员账号登录。
2. 首次登录后进入 `账号管理` 修改密码。
3. 检查自己的登录设备，陌生设备立即下线。
4. 如需开启 Samba，输入当前密码并确认状态。

安全建议：

- 不要共享管理员账号。
- 不要在共享文件夹存放密钥、数据库密码、备份包或账号表。
- 公网或不可信网络部署时，应使用 VPN、防火墙或反向代理访问控制。
- 对异常登录，先下线设备，再停用或重置相关账号。

## 3. 总览与资源判断

`总览` 展示全局资源快照：

- 节点总数、在线节点。
- GPU 总数、可用 GPU。
- 运行任务数量。
- 节点 CPU、可用内存、上传、下载。
- GPU 使用率、显存使用量、调度占用。

资源判断：

- 节点离线时，相关任务可能无法继续。
- GPU 显存高但无对应平台任务时，可能存在平台外进程或状态延迟。
- GPU 型号列表不准会导致用户筛选后任务长期等待。
- 网络或 NFS 异常会表现为任务启动慢、日志缺失、文件不可见。

## 4. 任务管理

管理员可查看所有任务。

任务区域：

- `等待区`：未运行或挂起任务。
- `执行区`：准备中、派发中、运行中任务。
- `历史区`：完成、失败、取消、节点掉线、调度错误等任务。

常用操作：

- `添加任务`：替用户或管理员自己提交任务。
- `批量添加`：批量提交多条命令。
- `修改选中任务`：修改等待、挂起或历史任务；历史任务修改后会重新进入等待或挂起状态。
- `挂起/取消挂起选中任务`：临时暂停或恢复等待任务。
- `删除选中任务`：删除等待或历史记录，可选择是否连带删除后继任务。
- `中止选中任务`：停止运行任务，会影响远端进程和日志。
- `重新提交`：从历史任务生成新任务。
- `查看任务日志`：查看 tail、刷新、下载或复制命令。

任务字段：

- **环境**：运行任务所需 Python/conda 环境。
- **项目路径**：命令执行目录。
- **命令**：单行命令。
- **节点**：可指定节点，也可留空。
- **GPU 数量**：`0` 表示 CPU 任务。
- **GPU 型号**：限制可用显卡类型。
- **前驱任务**：依赖任务成功后再运行。
- **紧急、复用、挂起**：影响排队和运行策略。

批量命令规则：

- 每行一条命令。
- 空行忽略。
- 以 `#` 开头的整行忽略。
- 行内 `#` 后内容作为注释忽略。

任务状态：

- `wait` / 等待：等待资源。
- `on_hold` / 挂起：保存但暂不运行。
- `dispatching` / 派发中：任务正在进入运行前准备阶段。
- `running` / 运行中：远端进程正在执行。
- `succeeded` / 完成：返回码为 0。
- `failed` / 失败：脚本或启动命令返回非 0。
- `cancelled` / 已取消：被用户或管理员中止。
- `offline` / 节点掉线：节点异常导致中断。
- `alloc_error` / 调度错误：实际资源使用和申请资源不一致。
- `lost` / 状态未知：重启或连接异常后无法确认。

## 5. 文件管理

管理员可维护平台可见文件，包括个人目录和共享文件夹。

常用操作：

- 进入目录、上级、刷新。
- 上传、下载、新建文件夹、新建文件。
- 文本文件预览、编辑和保存。
- 重命名、复制、移动、打包 zip、解压压缩包、删除。
- 在个人目录和共享文件夹之间转移资料。

注意：

- 文件操作直接影响用户任务。
- 删除、移动、覆盖保存前确认路径。
- 共享文件夹只放可公开给登录用户的资料。
- 大文件、二进制文件不建议在线编辑。
- 压缩包建议使用 zip、tar、tar.gz、tar.bz2、tar.xz。

文件问题排查：

- `path not found`：路径不存在或用户目录未创建。
- `path is outside shared folder`：路径超出共享目录边界。
- `target already exists`：目标文件已存在。
- `target cannot be inside source directory`：不能把目录复制或移动到自身内部。
- `unsupported archive type`：压缩包格式不支持。

## 6. 环境管理

管理员可查看和维护所有环境。

常用操作：

- `刷新环境列表`：重新加载环境。
- `导入环境`：扫描并登记已有 conda 环境。
- `检测`：检查 Python、PyTorch、TensorFlow、CUDA 和包列表。
- `查看日志`：查看环境操作日志。
- `创建副本`：为用户准备独立环境。
- `安装包`：安装 conda 包、pip wheel、本地包、源码包。
- `删除包`：先预览后删除，基础包受保护。
- `删除环境`：删除不再使用的环境。

环境状态：

- `available` / 可用：可选择运行任务。
- `registered` / 已登记：已纳入平台管理。
- `copying` / 复制中：正在创建副本。
- `importing` / 导入中：正在导入环境。
- `testing` / 检测中：正在执行环境检测。
- `installing` / 安装中：正在安装包。
- `failed` / 失败：最近操作失败，需看日志。

环境维护建议：

- 公共环境少改动，给用户实验时优先创建副本。
- 环境正在复制、导入、检测或安装时，不要重复操作。
- 安装失败先看环境日志，再看包格式、依赖版本和 Python 版本。
- 删除环境前确认没有任务仍在使用它。

## 7. 节点管理

进入 `管理员后台`，切换到 `节点管理`。

新增或修改节点时填写：

- **节点名称**：页面展示名，应稳定唯一。
- **IP 地址**：计算节点地址。
- **SSH 用户**：平台连接节点使用的用户。
- **与主节点最大连接带宽**：用于展示和辅助判断传输能力。
- **GPU 数量**：必须与实际 GPU 数一致。
- **GPU 型号列表**：按 `nvidia-smi` 顺序逐行填写。
- **使用权**：公开或私有。
- **共享**：不共享、组内共享或公开共享。
- **所有人**：私有或组内共享节点的归属用户。

操作说明：

- `修改`：更新节点信息和 GPU 型号。
- `强制下线`：用于断电、拔卡、维护、异常进程或节点不可用时；会影响该节点任务。
- `重连`：节点恢复后重新采集状态。
- `删除`：移除节点配置，删除前确认任务和审计线索是否还需要保留。

节点排查：

- 节点离线：检查网络、SSH、NFS、账号、驱动、`nvidia-smi`。
- GPU 数量不对：检查 GPU 数量和型号列表是否与实际顺序一致。
- 用户看不到节点：检查使用权、共享范围、所有人和导师学生关系。
- 任务总是不分到某节点：检查节点是否在线、调度是否允许、GPU 是否可用。

## 8. 用户管理

进入 `管理员后台`，切换到 `用户管理`。

可创建角色：

- **学生**：普通实验用户。
- **导师**：可管理自己名下学生。
- **管理员**：全局维护用户。
- **展示用户**：只进入展示大屏。

创建账号字段：

- 统一识别码。
- 用户名。
- 姓名。
- 角色。
- 导师关系，学生最多两名导师。
- 状态。
- 初始密码，至少 8 位。

编辑账号可修改：

- 用户名。
- 姓名。
- 角色。
- 导师关系。
- 启用或停用状态。

注意：

- 不要删除最后一个管理员。
- 停用账号前确认是否有关键任务正在运行。
- 删除账号前确认文件、环境、任务、导师关系和审计需要。
- 重置密码后提醒用户登录后自行修改。

## 9. 登录管理

进入 `管理员后台`，切换到 `登录管理`。

可以：

- 查看当前在线用户。
- 查看在线设备数、IP、设备和最后活跃时间。
- 按统一识别码、用户名或姓名查询某个用户登录设备。
- 下线指定设备。

处理异常登录：

1. 记录用户、IP、设备和时间。
2. 下线异常设备。
3. 视情况停用账号或重置密码。
4. 查看审计日志确认近期敏感操作。

## 10. 系统设置

进入 `管理员后台`，切换到 `系统设置`。

使用方式：

1. 选择配置键。
2. 阅读说明。
3. 按类型修改配置值。
4. 保存后刷新页面观察效果。

注意：

- 修改可能影响任务、文件、环境、登录或展示大屏行为。
- 生产环境修改关键配置前，应先确认回滚方式。
- 修改后建议查看审计日志，确认操作已记录。

## 11. 审计日志

进入 `管理员后台`，切换到 `审计日志`。

可按以下条件查询：

- 分类。
- 动作。
- 关键词。
- 开始时间。
- 结束时间。

排障时重点记录：

- 操作者。
- 动作。
- 对象类型和 ID。
- 时间。
- 结果。
- 详情。

审计用途：

- 追踪谁创建、修改、删除了用户。
- 追踪谁强制下线或修改了节点。
- 追踪任务中止、环境安装、文件删除等高风险操作。
- 还原问题发生前后的操作顺序。

## 12. 推荐运维流程

### 日常巡检

1. 看 `总览`：在线节点、GPU、运行任务是否正常。
2. 看 `管理员后台` 总览：用户、节点、在线用户、审计概况。
3. 进入 `节点管理` 检查离线节点。
4. 进入 `任务管理` 检查长时间等待、失败或节点掉线任务。
5. 进入 `审计日志` 查看近期高风险操作。

### 新用户入组

1. 创建学生或导师账号。
2. 学生绑定导师。
3. 告知初始密码和登录地址。
4. 提醒用户首次登录后改密码。
5. 根据需要分配私有节点或共享资料。

### 新节点上线

1. 确认节点网络、SSH、驱动、GPU 和共享目录。
2. 在 `节点管理` 新增节点。
3. 按实际顺序填写 GPU 型号。
4. 设置使用权、共享范围和所有人。
5. 保存后观察总览中的节点状态和 GPU 信息。
6. 提交小任务验证运行链路。

## 13. 常见问题排查

### 用户无法登录

- 检查账号是否启用。
- 检查密码是否正确，必要时重置。
- 检查是否存在异常登录设备。
- 检查后端认证服务是否正常。

### 用户看不到节点

- 检查节点是否在线。
- 检查节点使用权和共享范围。
- 检查私有节点所有人。
- 检查导师学生关系。

### 任务一直等待

- 检查是否有在线节点。
- 检查节点是否允许任务进入。
- 检查 GPU 数量和型号是否满足。
- 检查前驱任务是否成功。
- 检查任务是否挂起。
- 检查用户是否指定了离线节点。

### 任务运行后失败

- 先看任务日志。
- 再看环境日志和环境检测结果。
- 检查项目路径、命令、数据文件、输出目录。
- 检查 CUDA、PyTorch、TensorFlow 版本。
- 检查节点是否掉线或 NFS 异常。

### 任务出现调度错误

- 查看任务申请的 GPU 数量和型号。
- 查看实际运行节点和 GPU。
- 检查命令是否绕过资源限制。
- 检查是否有平台外进程占用 GPU。
- 必要时强制下线节点并清理异常进程。

### 节点离线

- 检查网络连通性。
- 检查 SSH 登录。
- 检查 NFS 挂载。
- 检查 NVIDIA 驱动和 `nvidia-smi`。
- 检查远端监控脚本。
- 节点恢复后点击 `重连`。

### 文件操作失败

- 检查路径是否存在。
- 检查目标是否已存在。
- 检查是否试图操作受保护根目录。
- 检查压缩包格式。
- 检查共享目录和用户目录权限。

### 环境操作失败

- 查看环境日志。
- 检查环境是否正在复制、导入、检测或安装。
- 检查包格式和依赖版本。
- 检查 Python 版本。
- 对多人共用环境，优先创建副本再处理。
