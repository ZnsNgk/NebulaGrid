# 导师使用手册

## 1. 导师账号能做什么

导师账号包含普通实验用户能力，并额外具备自己名下学生的管理与辅助排障能力。

你可以：

- 查看自己可用的节点、GPU 和任务情况。
- 管理自己的文件、环境和任务。
- 创建、查询、编辑、停用自己名下学生账号。
- 为学生重置密码。
- 查看或协助整理自己名下学生的文件。
- 根据学生任务日志、环境状态和资源状态辅助排查问题。

权限边界：

- 页面只会展示你有权限查看和操作的内容。
- 找不到某个学生、节点、任务或按钮时，先按当前页面可见范围排查；确需调整权限时联系管理员。
- 不建议通过接口或其他方式绕过页面权限。

## 2. 登录与账号安全

1. 使用管理员分配的导师账号登录。
2. 第一次登录后进入 `账号管理` 修改密码。
3. 在 `账号管理` 可修改姓名、Samba 状态和登录设备。
4. 发现陌生设备时，先下线设备，再修改密码。

第一次登录后的检查建议：

1. 确认账号角色显示为导师。
2. 修改初始密码。
3. 检查 `登录设备`，下线不认识的浏览器或 IP。
4. 进入 `学生管理`，确认自己名下学生列表是否完整。
5. 如果需要从 Windows 访问自己的个人目录，再开启 Samba；如果只是通过浏览器管理文件，可以先不开启。

学生无法登录时：

- 先在 `学生管理` 检查学生账号状态是否启用。
- 必要时为学生重置密码。
- 重置后提醒学生登录后自行修改密码。
- 如果学生不在你的列表中，联系管理员检查导师绑定关系。

## 3. Samba、Windows 网络共享与 SSH 登录

导师账号也可以像学生账号一样使用 Samba 和 SSH。Samba 适合从 Windows 文件资源管理器直接整理自己的个人目录；SSH 适合用终端传大文件、检查路径或快速验证脚本。学生遇到连接问题时，也可以按本节口径指导他们排查。

### 开启自己的 Samba

1. 登录 NebulaGrid。
2. 进入 `账号管理`。
3. 打开当前账号的 `Samba 服务` 开关。
4. 输入当前平台密码。
5. 保存后确认状态变为 `已启用`。

说明：

- 新账号默认不会自动开放 Samba。
- Samba 密码来自当前平台密码；平台改密后，已开启 Samba 的账号会同步更新。
- 页面显示 `失败` 时，通常不是学生自己能解决的问题，应记录用户名、时间和错误提示后交给管理员。

### 在 Windows 连接自己的目录

让用户直接访问自己的共享名，不要只访问服务器根路径：

```text
\\<master-ip>\<user_name>
```

示例：

```text
\\192.168.0.1\mentor1
```

也可以让 Windows 把共享目录映射成固定盘符：

1. 打开 `此电脑`。
2. 点击 `映射网络驱动器`。
3. 选择盘符，例如 `Z:`。
4. 文件夹填写 `\\192.168.0.1\mentor1`。
5. 勾选 `使用其他凭据连接`。
6. 输入平台用户名和平台密码。

Windows 登录窗口中：

- 用户名填写平台用户名，例如 `mentor1`。
- 密码填写平台密码。
- 如果需要带服务器名，可写成 `192.168.0.1\mentor1`。

Windows 缓存旧密码时，可在 `cmd` 中清理后重连：

```bat
net use \\192.168.0.1\mentor1 /delete /y
cmdkey /delete:192.168.0.1
net use \\192.168.0.1\mentor1 /user:mentor1 *
```

指导学生时重点确认四件事：

- 学生已经在 `账号管理` 中开启 Samba。
- 学生输入的是平台用户名，不是姓名、学号或 Windows 本地用户名。
- 共享地址写到了用户名这一层，例如 `\\192.168.0.1\test1`。
- 学生所在网络能访问主节点 445 端口；校外访问通常需要 VPN 或实验室内网。

### SSH 到自己的账号

在终端中执行：

```bash
ssh <user_name>@<master-ip>
```

示例：

```bash
ssh mentor1@192.168.0.1
```

登录密码使用平台密码。登录后默认目录通常就是 Web 文件管理中的个人目录。可用下面命令确认：

```bash
pwd
ls
```

用 `scp` 上传大文件：

```bash
scp ./course_data.zip mentor1@192.168.0.1:~/course_data.zip
```

用 `scp` 下载结果：

```bash
scp mentor1@192.168.0.1:~/outputs/report.csv ./report.csv
```

导师指导学生使用 SSH 时，应提醒学生：

- 普通训练不要直接在 SSH 里长期运行，应通过 `任务管理` 提交。
- 不要手动设置 `CUDA_VISIBLE_DEVICES` 绕过平台调度。
- 不要删除不认识的目录。
- 大文件传完后，在 Web `文件管理` 或 SSH 中确认路径，再提交任务。

## 4. 总览与节点监控

`总览` 用于判断当前可用资源和任务压力。

重点看：

- 在线节点和可用 GPU 是否足够。
- 节点 CPU、内存、网络是否异常。
- GPU 使用率和显存是否适合提交新任务。
- 学生反馈任务等待时，先看资源是否不足或节点是否离线。

使用建议：

- 指导学生提交任务前，先确认有合适 GPU。
- 学生指定了某个节点但任务一直等待时，确认该节点是否在线、是否对学生可见。
- 显存长期很高但没有对应任务时，记录节点名、时间和现象，交给管理员处理。

## 5. 学生管理

进入 `学生管理` 后，可以创建、查询、编辑、停用学生账号和重置密码。

### 创建学生

填写：

- **统一识别码**：可留空自动分配，也可按实验室规则填写。
- **用户名**：学生登录名。
- **姓名**：学生真实姓名。
- **状态**：一般选择启用。
- **初始密码**：至少 8 位。

创建成功后，学生会自动绑定到当前导师名下。

### 查询学生

可以按统一识别码、用户名、姓名关键词、状态筛选。

### 编辑学生

1. 在学生列表点击 `编辑`。
2. 系统会自动填入统一识别码。
3. 按需修改姓名或状态。
4. 点击保存。

注意：

- 导师只能管理自己名下学生。
- 停用学生后，学生不能继续登录。
- 停用前应确认学生是否仍有正在运行的重要任务。

### 重置密码

1. 在学生列表点击 `重置`，或在重置表单中填写学生统一识别码。
2. 输入新密码。
3. 提醒学生登录后立刻修改密码。

## 6. 文件管理与学生文件

默认进入你自己的个人目录。

点击 `查看学生文件` 后，可进入自己名下学生的目录，用于检查代码、配置、数据路径和输出结果。

可执行的操作包括：

- 进入文件夹、返回上级、刷新。
- 上传、下载、新建文件夹、新建文件。
- 预览和编辑文本文件。
- 重命名、复制、移动、打包、解压、删除。
- 打开脚本文件后，可在 `文件权限` 面板授予执行权限，便于主账户运行用户上传的 `.sh` 任务脚本。
- 在共享文件夹和个人目录之间复制资料。

协助学生时建议按这个顺序检查：

1. 当前路径是否是目标学生目录。
2. 代码入口文件是否存在。
3. 配置文件路径是否和任务命令一致。
4. 直接用 `./script.sh` 运行的脚本是否已授予主账户执行权限。
5. 数据路径是否存在，学生是否写错大小写。
6. 输出目录是否存在或有写入权限。

注意：

- 不要随意改动学生无关文件。
- 删除、移动、覆盖前先和学生确认。
- 重要修改建议让学生先备份或使用 Git。
- 共享文件夹不要放密码、密钥、账号表等敏感信息。
- 上传/下载大文件时，应使用 `scp` 命令，不建议通过前端上传/下载。

## 7. 环境管理

导师可以像普通用户一样查看和维护自己有权限的环境。

常用操作：

- `刷新环境列表`：重新加载环境。
- `导入环境`：从自己的文件目录选择 conda 环境 zip 并导入。
- `检测`：检查 Python、PyTorch、TensorFlow、CUDA 和包列表。
- `查看日志`：查看导入、检测、复制或安装包过程。
- `创建副本`：为课程、项目或学生实验准备独立环境。
- `安装包`：向可修改环境安装包。
- `删除包`：删除不需要的包，基础包会被保护。

### 指导学生从其他 Ubuntu 电脑导入环境

学生要从别的电脑带入已有环境时，建议按这个口径说明：

1. 环境来源必须是 Linux x86_64/amd64 电脑上的 Anaconda3 或 Miniconda3，目录通常是 `~/miniconda3/envs/<env_name>` 或 `~/anaconda3/envs/<env_name>`。
2. 在源电脑的 `envs` 目录下把整个环境目录打包，不要只打包子目录：

   ```bash
   cd ~/miniconda3/envs
   zip -r <env_name>.zip <env_name>
   ```

3. 用学生自己的平台账号把 zip 上传到主节点个人目录：

   ```bash
   scp <env_name>.zip <user_name>@<master-ip>:~/<env_name>.zip
   ```

4. 学生登录 Web 后进入 `环境管理`，点击 `导入环境`，选择个人目录里的 `/<env_name>.zip` 并确认。
5. 页面状态应从 `导入中` 到 `修复中`、`测试中`，最后变成 `可用`。如果失败，先看环境日志，再把环境名、zip 路径和日志最后几十行发给管理员。

需要特别提醒学生：Windows、macOS 环境包不能导入；Linux ARM、MIPS 等非 amd64 环境包也不能使用。系统会自动检测环境包是否适合当前 Linux 集群，检测不通过时不会显示为可用环境。

### 在指定节点编译安装环境包

当课程或项目依赖的包需要本机编译、CUDA 编译或 GPU 探测时，可以使用 `安装包` 页面里的 `指定节点编译`。这个功能适合处理源码包、需要 `nvcc` 的扩展包、或必须在某类节点上编译后才能运行的依赖。

操作步骤：

1. 进入 `环境管理`。
2. 选择要安装依赖的环境。
3. 点击 `安装包`。
4. 选择包来源和安装命令，例如 `pip install .`、`python setup.py install`、wheel 或源码包。
5. 在 `指定节点编译` 区域点击 `在指定节点`。
6. 等待系统实时探测主节点和可见计算节点。
7. 选择目标节点，并查看 `gcc`、`g++`、`clang`、`nvcc` 是否满足包的要求。
8. 选择 GPU 可见模式：`默认`、`CPU` 或指定具体 GPU。
9. 点击 `确认` 后再点击 `执行安装`。
10. 安装失败时打开环境日志，重点看编译器缺失、CUDA 路径、权限、NFS 路径或包版本冲突。

给学生解释时可以这样说：

- 普通 Python 包优先用普通安装。
- 只有源码包、CUDA 扩展或普通安装提示缺编译器时，才需要指定节点编译。
- 选择哪个节点，取决于包最终要在哪类节点上运行，以及该节点是否有需要的编译器和 CUDA。
- `CPU` 模式用于避免安装脚本误占 GPU；指定 GPU 模式只在安装脚本确实需要看到 GPU 时使用。

协助学生排查时重点看：

- 学生是否有权限看到目标节点。
- 目标节点是否在线。
- 弹窗里 `nvcc` 或必要编译器是否显示 `未安装`。
- 环境是否正处于 `安装中`，同一环境不能并发安装多个包。
- 日志中是否出现 `Permission denied`、`No such file or directory`、`nvcc not found`、`gcc not found`、CUDA 版本不匹配等信息。

指导学生排查环境时：

- 先确认学生任务选择了正确环境。
- 再看环境状态是否可用。
- 点 `检测` 看 Python 和 CUDA 相关结果。
- 安装包失败时看环境日志，不要只看页面上的简短错误。
- 编译安装失败时，记录环境名、目标节点、安装命令和日志最后几十行，再交给管理员判断节点工具链或共享路径问题。
- 公共环境不建议随意改；需要实验性安装时先创建副本。

## 8. 提交自己的任务

进入 `任务管理`，点击 `添加任务`。

字段说明：

- **选择环境**：任务运行环境。
- **项目路径**：代码目录，用文件夹选择器选择。
- **执行命令**：单行命令。
- **指定计算节点**：可留空，也可选择自己有权限使用的节点。
- **需求的 GPU 数量**：单卡填 `1`，CPU 任务填 `0`。
- **GPU 型号**：需要特定型号时选择；只选型号时系统会在学生可见节点中匹配该型号，和指定节点同时选择时只在该节点内匹配。
- **前驱任务**：设置任务依赖。
- **任务描述**：写清实验目的或参数。
- **紧急任务**：少量确需优先的任务才勾选。
- **复用 GPU**：确认任务资源占用较小再勾选。
- **挂起任务**：先保存，暂不运行。

不指定计算节点时，系统会优先尝试任务所有人的自有节点，其次是组内共享节点，再其次是组内他人公开共享的私有节点，最后才使用其他公开节点。

批量添加规则：

- 每行一条命令。
- 空行忽略。
- 以 `#` 开头的行忽略。
- 行内 `#` 后内容会作为注释忽略。

## 9. 管理自己的任务

任务分为 `等待区`、`执行区`、`历史区`。

常用操作：

- 等待区任务可修改、挂起、删除。
- 执行区任务可查看日志，必要时中止自己的任务。
- 历史区任务可查看结果、重新提交或删除记录。
- 双击任务行可打开日志。

任务状态解释：

- `等待`：等待资源。
- `挂起`：保存但暂不运行。
- `运行中`：正在执行。
- `完成`：正常结束。
- `失败`：脚本、路径、环境或依赖问题。
- `已取消`：主动中止。
- `节点掉线`：运行节点异常。
- `调度错误`：资源使用异常，命令或代码里不能有任何 `CUDA_VISIBLE_DEVICES`，否则会出现调度问题。

## 10. 协助学生排查任务

学生反馈任务失败时，建议按以下顺序：

1. 询问任务号。
2. 查看任务状态：等待、运行、失败、节点掉线还是已取消。
3. 打开任务日志，看最后几十行。
4. 检查项目路径是否正确。
5. 检查命令是否能找到脚本和配置文件。
6. 检查环境是否可用、是否缺包。
7. 检查 CUDA 或显存错误。
8. 如果节点异常、日志缺失或资源异常，记录节点名、任务号和时间，交给管理员。

常见日志关键词：

- `FileNotFoundError`：文件或路径不存在。
- `ModuleNotFoundError`：缺 Python 包。
- `CUDA out of memory`：显存不足，降低 batch size 或换更大显存 GPU。
- `Permission denied`：路径权限或文件权限问题。
- `No such file or directory`：脚本、配置或数据路径错误。

## 11. 推荐指导流程

1. 先让学生把代码、配置、数据说明放到自己的目录。
2. 检查学生项目路径和任务命令。
3. 检查环境，必要时创建环境副本。
4. 在总览确认资源状态。
5. 指导学生提交一个小任务试跑。
6. 看日志确认入口脚本、依赖和 CUDA 正常。
7. 再提交正式训练或批量任务。
8. 失败后先改代码、配置或环境，再重新提交。

## 12. 常见问题排查

### 无法创建学生

- 用户名或统一识别码可能重复。
- 初始密码长度不足。
- 当前账号可能不是导师角色。

### 找不到某个学生

- 该学生可能未绑定到你名下。
- 筛选条件可能过窄。
- 学生账号可能被管理员调整了角色或关系。

### 学生无法登录

- 检查账号是否启用。
- 重置密码后让学生重试。
- 学生仍无法登录时，记录用户名和时间，联系管理员。

### 无法查看学生文件

- 确认学生是否在你名下。
- 确认当前是否切换到了学生文件视图。
- 路径不存在时，让学生确认是否上传了文件。

### 学生任务一直等待

- 资源不足。
- 前驱任务未完成。
- 任务被挂起。
- 指定节点离线或学生不可见。
- 指定 GPU 型号在候选节点中没有满足条件的空闲显卡，或显存不足。

### 学生任务失败

- 先看任务日志。
- 再查项目路径、命令、环境、依赖、数据文件。
- 如果是节点掉线、日志缺失、资源异常，交给管理员。

### 环境安装包失败

- 查看环境日志。
- 确认包格式和 Python 版本。
- 复杂依赖先创建环境副本。
- 不要直接改动多人共用环境。
