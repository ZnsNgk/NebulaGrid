# 导师使用手册

## 1. 导师账号能做什么

导师账号包含普通实验用户能力，并额外具备自己名下学生的管理与辅助排障能力。

你可以：

- 查看自己可用的节点、GPU 和任务情况。
- 管理自己的文件、环境和任务。
- 创建、查询、编辑、停用自己名下学生账号。
- 为学生重置密码。
- 查看或协助整理自己名下学生的文件。
- 根据学生任务日志、环境状态和资源状态辅助排查问题。

权限边界：

- 页面只会展示你有权限查看和操作的内容。
- 找不到某个学生、节点、任务或按钮时，先按当前页面可见范围排查；确需调整权限时联系管理员。
- 不建议通过接口或其他方式绕过页面权限。

## 2. 登录与账号安全

1. 使用管理员分配的导师账号登录。
2. 第一次登录后进入 `账号管理` 修改密码。
3. 在 `账号管理` 可修改姓名、Samba 状态和登录设备。
4. 发现陌生设备时，先下线设备，再修改密码。

学生无法登录时：

- 先在 `学生管理` 检查学生账号状态是否启用。
- 必要时为学生重置密码。
- 重置后提醒学生登录后自行修改密码。
- 如果学生不在你的列表中，联系管理员检查导师绑定关系。

## 3. 总览与节点监控

`总览` 用于判断当前可用资源和任务压力。

重点看：

- 在线节点和可用 GPU 是否足够。
- 节点 CPU、内存、网络是否异常。
- GPU 使用率和显存是否适合提交新任务。
- 学生反馈任务等待时，先看资源是否不足或节点是否离线。

使用建议：

- 指导学生提交任务前，先确认有合适 GPU。
- 学生指定了某个节点但任务一直等待时，确认该节点是否在线、是否对学生可见。
- 显存长期很高但没有对应任务时，记录节点名、时间和现象，交给管理员处理。

## 4. 学生管理

进入 `学生管理` 后，可以创建、查询、编辑、停用学生账号和重置密码。

### 创建学生

填写：

- **统一识别码**：可留空自动分配，也可按实验室规则填写。
- **用户名**：学生登录名。
- **姓名**：学生真实姓名。
- **状态**：一般选择启用。
- **初始密码**：至少 8 位。

创建成功后，学生会自动绑定到当前导师名下。

### 查询学生

可以按统一识别码、用户名、姓名关键词、状态筛选。

### 编辑学生

1. 在学生列表点击 `编辑`。
2. 系统会自动填入统一识别码。
3. 按需修改姓名或状态。
4. 点击保存。

注意：

- 导师只能管理自己名下学生。
- 停用学生后，学生不能继续登录。
- 停用前应确认学生是否仍有正在运行的重要任务。

### 重置密码

1. 在学生列表点击 `重置`，或在重置表单中填写学生统一识别码。
2. 输入新密码。
3. 提醒学生登录后立刻修改密码。

## 5. 文件管理与学生文件

默认进入你自己的个人目录。

点击 `查看学生文件` 后，可进入自己名下学生的目录，用于检查代码、配置、数据路径和输出结果。

可执行的操作包括：

- 进入文件夹、返回上级、刷新。
- 上传、下载、新建文件夹、新建文件。
- 预览和编辑文本文件。
- 重命名、复制、移动、打包、解压、删除。
- 在共享文件夹和个人目录之间复制资料。

协助学生时建议按这个顺序检查：

1. 当前路径是否是目标学生目录。
2. 代码入口文件是否存在。
3. 配置文件路径是否和任务命令一致。
4. 数据路径是否存在，学生是否写错大小写。
5. 输出目录是否存在或有写入权限。

注意：

- 不要随意改动学生无关文件。
- 删除、移动、覆盖前先和学生确认。
- 重要修改建议让学生先备份或使用 Git。
- 共享文件夹不要放密码、密钥、账号表等敏感信息。
- 上传/下载大文件时，应使用scp命令，不建议通过前端上传/下载。

## 6. 环境管理

导师可以像普通用户一样查看和维护自己有权限的环境。

常用操作：

- `刷新环境列表`：重新加载环境。
- `导入环境`：登记系统扫描到的环境。
- `检测`：检查 Python、PyTorch、TensorFlow、CUDA 和包列表。
- `查看日志`：查看导入、检测、复制或安装包过程。
- `创建副本`：为课程、项目或学生实验准备独立环境。
- `安装包`：向可修改环境安装包。
- `删除包`：删除不需要的包，基础包会被保护。

指导学生排查环境时：

- 先确认学生任务选择了正确环境。
- 再看环境状态是否可用。
- 点 `检测` 看 Python 和 CUDA 相关结果。
- 安装包失败时看环境日志，不要只看页面上的简短错误。
- 公共环境不建议随意改；需要实验性安装时先创建副本。

## 7. 提交自己的任务

进入 `任务管理`，点击 `添加任务`。

字段说明：

- **选择环境**：任务运行环境。
- **项目路径**：代码目录，用文件夹选择器选择。
- **执行命令**：单行命令。
- **指定计算节点**：可留空，也可选择自己有权限使用的节点。
- **需求的 GPU 数量**：单卡填 `1`，CPU 任务填 `0`。
- **指定 GPU 型号**：需要特定显卡时选择。
- **前驱任务**：设置任务依赖。
- **任务描述**：写清实验目的或参数。
- **紧急任务**：少量确需优先的任务才勾选。
- **复用 GPU**：确认任务资源占用较小再勾选。
- **挂起任务**：先保存，暂不运行。

批量添加规则：

- 每行一条命令。
- 空行忽略。
- 以 `#` 开头的行忽略。
- 行内 `#` 后内容会作为注释忽略。

## 8. 管理自己的任务

任务分为 `等待区`、`执行区`、`历史区`。

常用操作：

- 等待区任务可修改、挂起、删除。
- 执行区任务可查看日志，必要时中止自己的任务。
- 历史区任务可查看结果、重新提交或删除记录。
- 双击任务行可打开日志。

任务状态解释：

- `等待`：等待资源。
- `挂起`：保存但暂不运行。
- `运行中`：正在执行。
- `完成`：正常结束。
- `失败`：脚本、路径、环境或依赖问题。
- `已取消`：主动中止。
- `节点掉线`：运行节点异常。
- `调度错误`：资源使用异常，，命令或代码里不能有任何`CUDA_VISIBLE_DEVICES`，否则会出现调度问题。

## 9. 协助学生排查任务

学生反馈任务失败时，建议按以下顺序：

1. 询问任务号。
2. 查看任务状态：等待、运行、失败、节点掉线还是已取消。
3. 打开任务日志，看最后几十行。
4. 检查项目路径是否正确。
5. 检查命令是否能找到脚本和配置文件。
6. 检查环境是否可用、是否缺包。
7. 检查 CUDA 或显存错误。
8. 如果节点异常、日志缺失或资源异常，记录节点名、任务号和时间，交给管理员。

常见日志关键词：

- `FileNotFoundError`：文件或路径不存在。
- `ModuleNotFoundError`：缺 Python 包。
- `CUDA out of memory`：显存不足，降低 batch size 或换更大显存 GPU。
- `Permission denied`：路径权限或文件权限问题。
- `No such file or directory`：脚本、配置或数据路径错误。

## 10. 推荐指导流程

1. 先让学生把代码、配置、数据说明放到自己的目录。
2. 检查学生项目路径和任务命令。
3. 检查环境，必要时创建环境副本。
4. 在总览确认资源状态。
5. 指导学生提交一个小任务试跑。
6. 看日志确认入口脚本、依赖和 CUDA 正常。
7. 再提交正式训练或批量任务。
8. 失败后先改代码、配置或环境，再重新提交。

## 11. 常见问题排查

### 无法创建学生

- 用户名或统一识别码可能重复。
- 初始密码长度不足。
- 当前账号可能不是导师角色。

### 找不到某个学生

- 该学生可能未绑定到你名下。
- 筛选条件可能过窄。
- 学生账号可能被管理员调整了角色或关系。

### 学生无法登录

- 检查账号是否启用。
- 重置密码后让学生重试。
- 学生仍无法登录时，记录用户名和时间，联系管理员。

### 无法查看学生文件

- 确认学生是否在你名下。
- 确认当前是否切换到了学生文件视图。
- 路径不存在时，让学生确认是否上传了文件。

### 学生任务一直等待

- 资源不足。
- 前驱任务未完成。
- 任务被挂起。
- 指定节点离线或学生不可见。
- GPU 型号条件太严格。

### 学生任务失败

- 先看任务日志。
- 再查项目路径、命令、环境、依赖、数据文件。
- 如果是节点掉线、日志缺失、资源异常，交给管理员。

### 环境安装包失败

- 查看环境日志。
- 确认包格式和 Python 版本。
- 复杂依赖先创建环境副本。
- 不要直接改动多人共用环境。
