## 1. 本次更新结论

本次检查以新上传的 `NebulaGrid-0523.zip` 为准。和 2026-05-22 后一版相比，这一版的核心推进集中在 **任务管理收口、Runtime Guard、环境安装 worker、部署脚本与文档工程化**。

上一版中，任务管理已经从内存任务 `_TASKS` 迁移到数据库，调度器和执行器也已经进入 MVP 阶段；但当时仍有几个关键缺口：

1. Runtime Guard 仍未真正检测 GPU 越权；
2. 调度器缺少显式多实例互斥保护；
3. 环境安装 worker 尚未真正消费数据库安装作业；
4. 任务日志还只是普通 tail，实时日志体验不完整；
5. 远端脚本同步和部署自检能力不足。

本轮代码已经补上了其中相当一部分：

1. `runtime_guard.py` 已实现 PID 树展开、`nvidia-smi --query-compute-apps` 采集、GPU UUID 比对、两轮复核、`alloc_error` 标记和远端进程组终止；
2. `scheduler.py` 已引入 `scheduler.instance_lock` 哨兵行，并在任务扫描时使用 `with_for_update(skip_locked=True)`；
3. `env_install_worker.py` 已从“扫描占位”推进到可领取 `EnvInstallJob`、执行本机或远端 compile 安装、写回状态和日志；
4. 本机环境包安装接口已经从同步执行改为创建 `EnvInstallJob`，由 worker 执行；
5. 任务日志增加 SSE 增量接口 `/api/tasks/{task_id}/log/events`；
6. 前端任务状态增加 SSE 变化监听 `/api/tasks/events`，任务页面能在任务变化时自动刷新；
7. 新增 `backend/scripts/sync_remote_scripts.py`，用于将 `remote/*.py` 同步到本机共享目录或计算节点；
8. 新增 `backend/scripts/deployment_self_check.py`，用于只读检查本机目录、远端脚本、SSH、NFS 共享路径和 `nvidia-smi` 可用性；
9. 部署文档、需求文档、架构文档已同步补充 scheduler、executor、runtime guard、env worker、SSE、部署自检和远端脚本同步说明；
10. `backend/tests/test_api.py` 增加了 Runtime Guard PID 树和 GPU 使用解析的单元测试。

因此，当前阶段判断为：

> **NebulaGrid 已经从“GPU 任务调度系统 MVP”继续推进到“调度执行 + 运行守护 + 环境安装 worker 初步闭环”的阶段。**

按照当前开发顺序，整体工程完成度可从上一版约 **80%–82%** 提升到约 **86%–88%**。

需要注意的是，当前仍不等于生产完成版。主要剩余问题包括：

- Runtime Guard 已实现核心检测逻辑，但还需要真实 GPU 节点联调和更多测试；
- Runtime Guard 当前主要发送 `SIGTERM`，尚未实现 grace period 后 `SIGKILL`；
- 调度器已有锁和 `skip_locked`，但仍需要真实多 worker 场景验证；
- 环境安装 worker 已能消费 DB job，但 `EnvPackageManifest` 仍未写入，包安装历史/回滚能力还不完整；
- `upload_package()` 仍是元数据登记，不是真正 multipart 上传；
- 远端 runner、env worker、monitor、guard 依赖 SSH、NFS 路径一致性和远端脚本同步，必须真实集群验收；
- 自动化测试仍偏少，尤其是调度器、执行器、Runtime Guard、环境安装 worker 的 mock/integration 测试需要继续补。

## 2. 本次主要新增或变化内容

| 方向 | 上一轮状态 | 当前状态 | 当前影响 |
|---|---|---|---|
| Runtime Guard | 仅有 guard 记录，未真正检测 GPU 越权 | 已实现远端 PID 树展开、GPU UUID 采集、两轮复核、`alloc_error` 和进程终止 | GPU 越权检测进入 MVP 阶段 |
| GPU 越权判定 | 未实现 | 基于 `TaskAllocation` 中 GPU ID 转 UUID，与远端 `nvidia-smi` 观察到的 GPU UUID 比对 | 不依赖 GPU index，降低重启后 index 漂移误判 |
| 越权处理 | 无 | 连续两轮发现未分配 GPU 后终止远端进程组、释放 allocation、写任务日志和 `TaskEvent` | 可实现“调度错误”终态 |
| 调度器互斥 | 缺少显式互斥 | 新增 `scheduler.instance_lock` 行锁，并使用 `with_for_update(skip_locked=True)` 扫描等待任务 | 降低多实例重复调度风险 |
| 环境安装 worker | 只扫描 queued job 或未实际执行 | 可领取 `EnvInstallJob`，执行本机 normal/local 安装或远端 compile 安装，并写回状态 | 环境包安装链路开始 worker 化 |
| 本机环境安装 | 同步 API 请求执行 | 改为创建 `EnvPackage` + `EnvInstallJob`，由 env worker 执行 | 大包安装不再长期占用 API 请求线程 |
| 远端 compile 安装 | 请求模型已有，链路不完整 | `env_install_worker.py` 支持 `target_node_id + compile` 时 SSH 到目标节点执行命令 | compile 模式有初步后端路径 |
| 环境安装状态 | API 同步返回结果为主 | `EnvInstallJob` 写 `queued/running/succeeded/failed/cancelled`、return_code、started_at、finished_at | 前端可围绕 job 状态做轮询 |
| 任务日志实时化 | 只有普通日志 tail | 新增 `/tasks/{task_id}/log/events` SSE 增量日志流 | 具备实时日志基础 |
| 任务列表实时化 | 前端主要刷新/轮询 | 新增 `/tasks/events` SSE，基于可见任务总数、max_task_id、max_event_id 判断变化 | 前端任务区能自动轻量刷新 |
| 远端脚本同步 | 主要靠手工部署 | 新增 `backend/scripts/sync_remote_scripts.py` | 可同步 `remote/*.py` 到本机共享目录或计算节点 |
| 部署自检 | 缺少系统性检查 | 新增 `backend/scripts/deployment_self_check.py` | 上线前可检查 SSH、共享目录、远端脚本和 `nvidia-smi` |
| 测试 | 任务/guard 自动化较少 | 新增 Runtime Guard PID 树和 GPU app 解析单元测试 | 运行守护核心解析逻辑有基础测试 |
| 文档 | 任务 MVP 描述较新 | 部署、需求、架构文档均更新 scheduler/executor/guard/env worker/SSE/self-check | 文档与当前实现更接近 |

### 当前任务主链路状态

当前已经具备如下闭环：

```text
用户提交任务
  ↓
Task / TaskRequirement / TaskDependency / TaskEvent 入库
  ↓
Scheduler 获取 scheduler.instance_lock
  ↓
SELECT wait tasks FOR UPDATE SKIP LOCKED
  ↓
检查前驱依赖
  ↓
筛选用户可见且 online/scheduling_enabled 的节点
  ↓
按 GPU 数量、型号、复用策略、显存指标选择 GPU
  ↓
写 TaskAllocation / TaskRuntimeGuard
  ↓
任务状态 wait → dispatching
  ↓
Executor 扫描 dispatching
  ↓
SSH 调用远端 runner.py
  ↓
runner 在计算节点后台运行 wrapper
  ↓
任务状态 dispatching → running
  ↓
runner 写日志和 status JSON
  ↓
Runtime Guard 周期性检查 PID 树实际 GPU 使用
  ↓
Executor 读取 status
  ↓
任务状态 running → succeeded / failed / alloc_error / offline_error
  ↓
释放 TaskAllocation
```

### 当前需要特别注意的问题

| 问题 | 影响 | 建议 |
|---|---|---|
| Runtime Guard 需要真实 GPU 节点联调 | 解析逻辑有测试，但 SSH/nvidia-smi/UUID/进程组要实测 | 设计越权用例，确认 `alloc_error` 和 kill 生效 |
| 越权终止当前主要 SIGTERM | 恶意或卡死进程可能不退出 | 增加 grace period 后 SIGKILL |
| 调度器锁需要真实多实例验证 | 理论上已有锁，但部署形态可能复杂 | 保持 systemd 单实例，并补并发调度测试 |
| runner 依赖共享路径一致性 | NFS 路径不同会导致日志/status 丢失 | 部署前必须跑 self-check |
| 取消运行中任务依赖 executor 轮询 | 不够实时 | 可后续接事件通知或缩短 executor interval |
| 任务日志 SSE 需要 Nginx 配置验证 | 代理缓冲会影响实时性 | 确认 `X-Accel-Buffering: no` 和 Nginx proxy buffering |
| CPU-only 任务仍分配节点 | 合理但需前端解释 | 标明 CPU 模式和节点来源 |
| 任务测试仍不足 | 调度执行链路风险高 | 补数据库任务、调度、执行器、依赖、日志、guard 测试 |

### 阶段判断

任务管理已经从 **调度执行 MVP** 进一步推进到 **调度执行 + 运行守护 MVP**。  
下一步重点不再是“能不能跑”，而是“真实集群能否稳定跑、出错能否恢复、越权能否稳定拦截”。

## 7. 当前最值得肯定的改进

### 7.1 Runtime Guard 已经从占位变成 MVP

本轮最大价值之一是 Runtime Guard 不再只是扫描 guard 记录，而是开始真正做运行时一致性检查：

1. 通过 SSH 在计算节点执行 `ps -eo pid=,ppid=`；
2. 从 root PID 展开完整 PID 树；
3. 调用 `nvidia-smi --query-compute-apps=pid,gpu_uuid,used_memory`；
4. 只保留该任务 PID 树实际使用的 GPU UUID；
5. 将实际 GPU UUID 与 allocation 中允许 GPU 的 UUID 比对；
6. 第一次发现越权写 warning；
7. 连续两轮发现越权后标记 `alloc_error`；
8. 终止远端进程组；
9. 释放 allocation；
10. 写任务日志和 `TaskEvent`。

这直接对应用户最初提出的“如果用户卡 bug 把任务弄到别的 GPU，就直接中止并显示调度错误”。

### 7.2 调度器增加了事务互斥

调度器现在不只是扫 `wait` 任务，还增加了：

- `scheduler.instance_lock` 行锁；
- `with_for_update(skip_locked=True)`；
- 调度器开关 `scheduler.enabled`；
- 可配置调度间隔 `scheduler.interval_seconds`。

这比上一版更接近生产部署形态。

### 7.3 环境安装 worker 开始真正工作

环境安装不再完全依赖 API 同步执行。现在本机安装会创建：

- `EnvPackage`；
- `EnvInstallJob`；
- `queued` 状态；
- log_path；
- command；
- workdir。

然后 `env_install_worker.py` 通过行锁领取 job 并执行安装，写回 running/succeeded/failed、return_code 和 finished_at。这个方向是正确的。

### 7.4 任务日志和任务状态进入 SSE 阶段

本轮任务系统开始支持：

- `/api/tasks/events`：任务变化事件；
- `/api/tasks/{task_id}/log/events`：日志增量事件。

这让任务页面从传统刷新向实时界面推进。

### 7.5 部署工程化开始补上

新增两个非常关键的部署脚本：

- `sync_remote_scripts.py`：同步远端执行脚本；
- `deployment_self_check.py`：只读检查 SSH、共享路径、远端脚本和 GPU 工具。

这对真实集群落地很重要，因为 scheduler/executor/guard/env worker 都依赖远端脚本和共享目录一致。

## 8. 当前主要风险

| 风险 | 所属阶段 | 影响 | 建议 |
|---|---|---|---|
| Runtime Guard 需要真实 GPU 节点验证 | 任务管理 | 逻辑正确不代表生产环境稳定 | 构造越权任务实测 `alloc_error`、日志、kill、allocation 释放 |

| systemd unit 文件未仓库化 | 部署工程 | 文档有命令但缺可直接版本化文件 | `deploy/systemd` 下补 service 模板 |
