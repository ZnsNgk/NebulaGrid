## 1. 本次更新结论

本次检查以新上传的 `NebulaGrid-0523_3.zip` 为准。  
和上一版 `NebulaGrid-0523-2.zip` 相比，这一版的核心变化不是继续大幅改动 Runtime Guard 或任务调度主链路，而是围绕 **展示大屏、共享文件夹、文件 IO 生产化、监控历史曲线和权限隔离** 进行补强。

上一版已经将 NebulaGrid 推进到“真实集群联调与生产化加固阶段”；这一版进一步补上了几个实际部署中非常重要的配套能力：

1. **新增展示者 viewer 角色**，该角色只有 `presenter:read` 权限，不能访问普通节点、任务、环境、文件等业务 API。
2. **新增展示者大屏接口 `/api/dashboard/presenter`**，一次性返回全局节点、GPU、任务统计、节点状态、GPU 状态以及 InfluxDB 历史曲线。
3. **前端新增 presenter 页面**，viewer 登录后自动进入 `#/presenter`，展示集群节点墙、CPU/内存/网络/GPU 使用率、GPU 显存柱状图和刷新控制。
4. **viewer 会话改为长期有效逻辑**，不会因为普通 30 分钟在线窗口而被动离线，适合公共展示屏长期登录。
5. **新增共享文件夹根目录 `NEBULAGRID_SHARED_FOLDER_ROOT`**，用户可以进入共享文件夹视图，查看共享数据，并支持个人目录与共享目录之间复制。
6. **文件操作改为专用线程池执行**，避免大文件预览、上传、复制、打包、解压等磁盘 IO 占用 FastAPI 默认请求线程池。
7. **InfluxDB 增加历史曲线查询**，支持按配置窗口聚合节点和 GPU 历史监控数据，供展示大屏绘制 sparkline。
8. **dashboard schema 拆分更清晰**，普通 dashboard summary 和 presenter 大屏模型分离。
9. **测试覆盖新增 viewer 权限隔离与共享文件夹双向复制场景**。
10. **文档同步补充展示大屏、viewer 账号、共享文件夹、文件 IO 线程池、InfluxDB 历史查询相关说明。**

因此，当前阶段判断为：

> **NebulaGrid 已经从“真实集群联调与生产化加固阶段”继续推进到“面向实际展示、共享数据和多角色使用场景的完善阶段”。**

按照当前开发顺序和整体功能闭环，工程完成度可从上一版约 **84%–86%** 提升到约 **86%–88%**。

需要注意的是，本轮新增的展示大屏和共享文件夹属于生产可用性增强，不代表任务调度主链路已经完全结束。后续仍需要继续验证真实集群中的 Runtime Guard、SSH runner、NFS 路径、SSE 反代、环境 compile 安装、任务取消与恢复等关键问题。

## 2. 本次主要新增或变化内容

| 方向 | 上一轮状态 | 当前状态 | 当前影响 |
|---|---|---|---|
| viewer 角色 | 角色枚举中已有 viewer 但权限和入口较弱 | viewer 只拥有 `presenter:read`，登录后自动进入展示大屏 | 可创建公共展示屏账号，不暴露业务管理能力 |
| 展示者大屏接口 | 普通 dashboard summary 为主 | 新增 `/api/dashboard/presenter` | 大屏一次性获取节点、GPU、任务和历史监控数据 |
| 大屏历史曲线 | InfluxDB 主要读最新值 | 新增 `get_historical_metrics()` 和 `build_history_query()` | 支持 CPU、内存、网络、GPU 使用率、显存、进程数历史曲线 |
| presenter 前端页面 | 无专用页面 | 新增 `renderPresenter()`、节点墙、GPU 使用率面板、显存柱状图、sparkline | 浏览器可作为集群状态展示屏 |
| viewer 会话 | 普通 session 活跃窗口 | viewer 会话使用 `never_expires` 逻辑 | 展示屏静默很久后仍保持登录 |
| viewer 权限隔离 | 需要确认 | 测试验证 viewer 可访问 presenter，但不能访问 `/nodes`、`/tasks` | 降低公共屏账号误操作风险 |
| 共享文件夹 | 只有个人文件和导师学生文件视图 | 新增 `shared` 文件 scope 和 `shared_folder_root` | 支持全员共享数据入口 |
| 共享文件复制 | 无 | 支持个人目录复制到共享文件夹、共享文件夹复制到个人目录 | 便于分发数据集和收集结果 |
| 文件 scope 字段 | 文件操作请求只区分 path/target_path | `FileOperationRequest` 新增 `scope` 和 `target_scope` | 支持跨个人/共享 scope 的复制 |
| 文件 IO 执行器 | 文件操作直接在请求路径中执行 | 新增 `file_executor.py`，使用专用线程池 | 降低大文件 IO 对 API 请求线程的影响 |
| 文件线程池配置 | 无 | 新增 `NEBULAGRID_FILE_OPERATION_WORKER_THREADS` | 可按机器磁盘性能调节文件 IO 并发 |
| 文件 executor 生命周期 | 无 | FastAPI shutdown 时关闭文件操作线程池 | 热重载/停服时不再残留接收新任务的旧线程池 |
| 共享文件测试 | 无 | 新增共享文件夹双向复制测试 | 验证 shared scope 路径边界和复制逻辑 |
| dashboard 测试 | 基础接口测试 | 新增 viewer 只能访问 presenter 的测试 | 权限隔离有回归保护 |
| 文档 | 主要围绕任务/环境/部署 | 补充展示大屏、共享文件夹、文件线程池、InfluxDB 历史曲线 | 更贴近实际部署说明 |

## 7. 当前最值得肯定的改进

### 7.1 展示大屏补齐了实验室公共屏需求

viewer 账号和 presenter 页面非常适合挂在实验室大屏上展示集群状态。  
它只返回只读聚合数据，不返回用户任务明细，权限边界比较清晰。

### 7.2 InfluxDB 历史曲线开始被真正消费

此前 InfluxDB 主要用于最新监控快照。现在 presenter 大屏会查询历史窗口并渲染 sparkline，这使节点监控从“状态展示”升级为“趋势展示”。

### 7.3 共享文件夹补齐了数据集分发场景

实验室环境下常见需求是共享数据集、wheel 包、requirements、公开脚本或结果模板。  
共享文件夹 scope 使用户能从公共区域复制到自己的工作目录，也能将结果复制到共享区域。

### 7.4 文件操作线程池提升了 API 稳定性

大文件上传、复制、预览、压缩、解压本质都是磁盘 IO。  
把这些操作放到专用线程池后，API 默认请求线程池不容易被大文件操作占满，生产稳定性会更好。

### 7.5 viewer 长期会话符合展示屏场景

展示屏一般长时间不交互，如果按普通用户 30 分钟活跃窗口处理，会频繁掉线。  
viewer 只拥有极低权限，因此长期会话在这个场景下比较合理。

## 8. 当前主要风险

| 风险 | 所属阶段 | 影响 | 建议 |
|---|---|---|---|
| viewer 长期会话 | 用户/安全 | 公共屏设备如果被物理接触，仍可能泄露只读状态信息 | 使用专用 viewer 账号，限制权限，必要时限制 IP |
| presenter 历史查询性能 | 节点/监控 | 节点多、GPU 多时 InfluxDB 查询可能变重 | 控制 range/window，必要时做缓存 |
| 共享文件夹写入策略 | 文件管理 | 如果所有用户都能复制到共享区，可能被误写或塞满磁盘 | 明确共享区写权限、配额和清理策略 |
| 文件线程池并发配置 | 文件管理 | 线程数过大可能导致磁盘 IO 抖动 | 根据磁盘性能设置 `NEBULAGRID_FILE_OPERATION_WORKER_THREADS` |
| Runtime Guard 依赖 GPU UUID 同步 | 任务管理 | GPU UUID 缺失会进入 uuid_pending，无法判断越权 | 部署时必须确认 monitor 同步 GPU UUID |
| SSE 可能被 Nginx 缓冲 | 任务/大屏 | 日志或事件实时性失效 | Nginx 配置禁缓冲 |
| EnvPackageManifest 未接入 | 环境管理 | 安装包无法精确追踪和回滚 | 安装成功后写 manifest |
| Alembic 仍未引入 | 工程化 | 手写补列长期不可维护 | 尽快迁移到 Alembic |
| 自动化测试仍不足 | 全局 | 调度、执行、guard、worker 很难回归 | 补单元测试和集成测试 |
