## 8. 当前最值得肯定的改进

### 8.1 实机任务主链路已经跑通

这是本轮最核心的成果。  
任务系统不再只是代码逻辑闭环，而是已经在真实节点上验证：

- CPU-only；
- 单 GPU；
- 双 GPU；
- 失败回收；
- 取消任务；
- 日志下载；
- 实时日志；
- 重新提交；
- Runtime Guard。

这说明 NebulaGrid 已经具备真实调度系统的核心能力。

### 8.2 Runtime Guard 通过真实越权测试

之前 Runtime Guard 是最大风险之一。  
本轮报告中已经验证了用户故意覆盖 `CUDA_VISIBLE_DEVICES=1` 的场景，并成功触发 `alloc_error`。

这对实验室内部系统非常重要，因为它解决了用户绕过调度使用其他 GPU 的关键漏洞。

### 8.3 节点 GPU 管理更贴近真实硬件

从“管理员手填 GPU 型号”转为“monitor 扫描 GPU，管理员只标记可调度 0/1”，这是非常合理的实机调整。  
它可以解决：

- 节点上有显示卡；
- 某张 GPU 不希望调度；
- GPU 型号/UUID 以 nvidia-smi 为准；
- 管理员手填错误导致调度错位。

### 8.4 强制下线节点语义更完整

强制下线现在不只是把节点状态改掉，而是会：

1. 找到该节点未释放 allocation；
2. 找到相关任务；
3. 尝试 kill 远端进程组；
4. 将任务置为 cancelled；
5. 释放 allocation；
6. 写入任务事件；
7. 记录审计详情。
