# 3. 本轮最大新增：任务 ETA 预测系统

这是本轮最核心的新功能。

之前任务系统只能展示：

- 等待；
- 运行；
- 已完成；
- 已失败。

用户无法提前知道：

- 任务大概还需要多久；
- GPU 长任务什么时候释放；
- 当前训练是否异常慢。

本轮新增完整 ETA 子系统。

# 3.2 支持的进度来源

系统目前支持：

## 方式1：训练日志解析

例如：

```
Epoch 50/100
step 1000/5000
progress 30%
```

自动解析：

- 当前 epoch；
- 当前 step；
- 总 epoch；
- 总 step；
- 当前速度。

---

## 方式2：显式进度文件

任务可以生成：

```
progress.json
```

例如：

```json
{
 "progress":0.56,
 "message":"training"
}
```

系统读取后更新。

---

## 方式3：任务时间模型

新增：

```python
task_timing.py
```

用于估计：

- 已运行时间；
- 平均速度；
- 剩余时间；
- 完成时间。

---

# 3.3 ETA 预测算法

当前采用简单稳定策略：

```
剩余时间 =
剩余工作量 / 当前平均速度
```

同时加入：

- 平滑窗口；
- 异常速度过滤；
- 最小运行时间要求。

避免：

刚启动：

```
step=1
耗时30秒
```

直接预测：

```
剩余999小时
```

这种错误。

# 8. 当前新增风险

## 8.1 ETA 解析依赖日志格式

风险：

不同训练代码：

```
tqdm
lightning
mmengine
自定义logger
```

格式不同。

建议：

未来增加：

```
progress adapter
```

允许用户选择：

- PyTorch Trainer；
- MMEngine；
- 自定义 JSON。

---

## 8.2 Usage 数据量增长

长期运行后：

- 任务数；
- metrics；
- rollup

会增加。

建议：

增加：

- 数据保留策略；
- 月度归档；
- InfluxDB retention policy。

---

## 8.3 Usage 与 GPU 计费模型

目前：

统计资源。

未来如果用于实验室资源分配：

可以增加：

```
GPU credits
```

例如：

```
RTX4090:
1小时 = 10 credits

P40:
1小时 = 2 credits
```

---

## 8.4 ETA 不应作为硬性承诺

ETA 是预测：

不是：

```
保证结束时间
```

UI 中建议：

显示：

```
预计剩余时间
```

而不是：

```
完成时间
```

避免用户误解。
