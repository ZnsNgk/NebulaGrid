## 1. 本次更新结论

本次检查以新上传的 `NebulaGrid-0523_4.zip` 为准。  
从代码结构、文档、前端页面、测试和部署说明看，当前 NebulaGrid 的主题开发已经基本完成，项目正在从“功能开发阶段”转入 **生产环境联调联试阶段**。

和上一版相比，本轮主要新增和强化点集中在：

1. **Samba/SMB 账号管理**：用户可在账号管理中开启/关闭 Samba；开启时需要输入当前密码；系统可在配置允许时执行 `smbpasswd/pdbedit`；密码修改或管理员重置密码时可同步 Samba 密码。
2. **用户与共享文件部署闭环增强**：配置中明确 `shared_folder_root`，文档中明确 `/home/ddltm/shared` 作为实验室共享文件目录；文件管理页已支持共享文件夹视图。
3. **生产部署文档进一步完善**：部署文档已覆盖 Samba、NFS、主账户目录部署、远端脚本同步、systemd、Nginx、PostgreSQL、InfluxDB、Redis 等。
4. **系统设置增强**：`manage.samba_accounts`、`file_operation_worker_threads`、共享目录等配置进入统一配置体系。
5. **账号管理体验增强**：当前用户公开信息中包含 Samba 状态，前端错误文案已覆盖 Samba 命令失败、账号不可用、密码错误等场景。
6. **测试覆盖继续补强**：测试中新增 Samba 开关、Samba 密码同步、展示用户权限、Runtime Guard PID 树等用例。

结合你补充的实际部署场景：

- 系统主要用于实验室或课题组；
- 用户规模约为几名导师和几十名学生；
- 大文件或大量文件建议使用 `scp` 传输；
- Web 文件管理主要用于脚本、配置、少量结果、环境包选择和小规模维护；
- 用户需要对自己的环境负责，不会随意操作他人环境；
- 不面向公网多租户，也不面向不可信用户群体；

因此，之前提到的部分风险需要下调优先级：

| 风险项 | 之前评估 | 结合实际场景后的优先级 |
|---|---|---|
| 压缩炸弹 | 偏生产安全风险 | 低优先级增强项；实验室可信内网环境一般不会出现 |
| Web 大文件上传压垮后端 | 中高风险 | 中低优先级；大文件走 scp，不把 Web 文件页作为数据集传输通道 |
| 文件重 IO 任务过多 | 中高风险 | 中低优先级；用户规模较小，文件操作线程池已足够初期使用 |
| 环境安装/删除包的精细 manifest | 中高风险 | 中低优先级；用户自负环境，基本日志足够，精细追踪可后续补 |
| 环境包删除审计 | 中等风险 | 低到中优先级；保留操作日志即可，不必作为上线阻塞项 |
| 多租户恶意攻击防护 | 高安全要求 | 当前不是目标场景，不作为联调前阻塞项 |

当前更重要的是：

> 在真实主节点和计算节点上验证 SSH、NFS、Samba、conda 环境、任务调度、Runtime Guard、日志、InfluxDB 指标和前端操作是否稳定闭环。

因此，当前阶段判断为：

> **NebulaGrid 主题功能开发基本完成，已具备进入实验室生产环境联调联试的条件。**

当前整体完成度按“功能开发完成度”估计为 **88%–90%**；  
按“生产联调准备度”估计为 **82%–85%**。

## 2. 本次主要新增或变化内容

| 方向 | 上一阶段状态 | 当前状态 | 当前影响 |
|---|---|---|---|
| Samba 账号管理 | 之前主要是 Linux 子账户和 Web 登录账号 | 新增 `samba_service.py`，支持启用、禁用、删除、改密同步和状态检查 | 用户可通过 SMB/Samba 访问自己的工作目录 |
| 当前用户 Samba 开关 | 无完整自助接口 | 新增 `/api/auth/samba/status` 和 `/api/auth/samba/update` | 用户可在账号页自助开启/关闭 Samba |
| Samba 密码同步 | 不完整 | 用户自助改密、管理员重置密码时会调用 `set_samba_password` | 避免 Web 密码和 Samba 密码不一致 |
| Samba 管理总开关 | 无 | 新增 `NEBULAGRID_MANAGE_SAMBA_ACCOUNTS` 和 DB 设置 `manage.samba_accounts` | 开发环境可干运行，生产环境可打开真实管理 |
| Samba 状态字段 | 无 | 用户表新增 `samba_enabled`、`samba_status`、`samba_last_error`、`samba_updated_at` | 前端可展示 SMB 状态和错误原因 |
| Samba 命令执行安全 | 无 | 限制账号名正则，命令走绝对路径，非 root 使用 `sudo -n` | 避免 Web 请求卡在交互式 sudo 密码 |
| 共享文件夹配置 | 基础支持 | `shared_folder_root` 进入配置，默认 `/home/ddltm/shared` | 与实验室共享资料目录需求匹配 |
| 文件管理共享视图 | 已有雏形 | 支持共享文件夹 scope | 用户可通过 Web 只读查看共享文件夹内容 |
| 部署文档 | 已较完整 | 进一步补充 Samba、共享目录、主账户目录部署和 systemd/Nginx 说明 | 更适合生产联调 |
| 设置页 | 已增强 | 增加 `manage.samba_accounts`、文件线程池等配置说明 | 管理员可明确知道哪些能力是否由系统真实执行 |
| 测试 | 已覆盖较多 | 新增 Samba 开关、Samba 密码同步、展示用户、Runtime Guard PID 树测试 | 关键新增功能有回归测试雏形 |
| 风险口径 | 偏通用生产安全 | 调整为实验室/课题组可信环境 | 压缩炸弹、大规模 IO、包级精细审计不再作为上线阻塞项 |

## 7. 当前最值得肯定的改进

### 7.1 Samba/SMB 开始融入账号体系

这是本轮最重要的新变化。  
用户可以通过账号管理开启 Samba，系统可以在生产配置允许时创建和维护 Samba 用户。这样用户既可以通过 Web 页面管理文件，也可以通过 SMB/Samba 或系统账号方式访问自己的目录。

对于实验室场景，这比强行让所有文件操作都走 Web 更合理。

### 7.2 风险设计更符合实验室使用方式

现在系统已经逐渐形成清晰边界：

- Web 文件管理：轻量操作、查看、脚本、配置、小包、日志；
- scp：大量文件、大文件、数据集；
- Samba：日常挂载和文件访问；
- Web 环境管理：环境检测、离线包安装、查看日志；
- Web 任务管理：提交、调度、查看日志、取消、重提；
- 管理员后台：用户、节点、设置、审计和展示大屏。

这个定位适合几名导师和几十名学生的实验室。

### 7.3 部署文档开始贴近真实上线

文档已经覆盖：

- 主账户目录部署；
- NFS；
- PostgreSQL；
- InfluxDB；
- Redis；
- Nginx；
- systemd；
- Samba；
- 远端脚本同步；
- 部署自检；
- 用户 home；
- 共享文件夹。

这为生产联调提供了比较扎实的基础。

## 8. 当前主要风险与调整后优先级

| 风险 | 所属阶段 | 调整后优先级 | 说明 |
|---|---|---:|---|
| SSH/NFS/路径不一致 | 部署/任务 | 高 | 真实联调必须优先验证 |
| GPU UUID 未同步导致 Runtime Guard 无法判断 | 节点/任务 | 高 | 直接影响 GPU 越权检测 |
| Samba sudoers / smbd 配置不正确 | 用户/文件 | 高 | 影响用户 SMB 访问，需要联调 |
| systemd 服务未完全收口 | 部署 | 高 | 生产运行需要稳定启停 API/worker |
| Nginx SSE 缓冲导致日志不实时 | 任务/前端 | 中高 | 影响体验，但不影响任务执行 |
| 节点字段校验返回 500 | 节点 | 中 | 影响前端提示，建议修 |
| Alembic 未引入 | 工程化 | 中 | 后续版本升级会痛，但首次联调可先手动初始化 |
| EnvPackageManifest 未完整接入 | 环境 | 中低 | 用户自负环境，不作为联调阻塞 |
| 压缩炸弹 | 文件/环境 | 低 | 实验室可信环境，非首要风险 |
| Web 大文件上传压力 | 文件 | 低 | 明确建议大文件走 scp |
| 文件重 IO 并发 | 文件 | 低 | 用户规模小，线程池足够初期使用 |
| 环境包安装/删除精细审计 | 环境 | 低 | 现有日志足够排错，后续增强即可 |

当前 NebulaGrid 3.0 的阶段完成度约为 **88%–90%**。

分阶段看：

| 阶段 | 完成度 |
|---|---:|

| 文件管理 | 84%–86% |

本轮最核心的变化是：

1. Samba/SMB 账号管理接入；
2. 用户自助开启/关闭 Samba；
3. 用户改密和管理员重置密码时同步 Samba；
4. 用户表和前端公开信息增加 Samba 状态；
5. 共享文件夹和主账户部署文档进一步完善；
6. 系统设置中加入 Samba 管理开关；
7. 测试覆盖新增 Samba 相关用例；
8. 项目整体从“生产化加固”进入“准备真实生产联调”的阶段。

结合实际部署环境，后续不需要把精力优先放在压缩炸弹、大规模 Web 文件 IO、环境包精细审计等低概率问题上。更重要的是把真实实验室环境跑通：

> Linux 账号 → Samba → NFS → 节点监控 → InfluxDB → 环境检测 → 任务提交 → 调度 → 远端执行 → 实时日志 → Runtime Guard → 任务回收。

只要这条链路在真实机器上稳定跑通，NebulaGrid 就可以进入课题组内部试运行阶段。
